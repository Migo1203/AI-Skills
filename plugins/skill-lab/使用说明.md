# 个人电商技能使用说明 · v0.4.0

## 最快开始

在已安装本技能的工作区中，统一调用：

> 使用 $ecommerce-visual-strategy。平台是【平台/站点】，产品是【SKU/型号】，资料在【文件/目录】。本次需要【文案/主图/套图/详情页/A+】。按“AI策划→AI按规划生图→可编辑SVG交付→我审稿调整→我指定定稿→AI检查”执行，先做到可供我审阅的完整交付。已有合格素材直接复用，缺失参数不要编造。

在已启用技能及相应项目指令的工作区，也可以直接说“帮我做天猫详情页”或“为Amazon美国站写标题五点并制作A+”，再按同一入口处理。显式写技能名更方便在新聊天中明确任务。是否读了某个参考以本次实际读取为准，不能仅凭文件存在声称已加载。

旧`amazon-listing-studio`已合并，不必再单独安装；在Migo本地AIGC项目中，历史名称会按项目指令转到此统一技能。不是全局别名：其他工作区应调用统一名称、安装完整目录，并具备实际生图/渲染能力。

## 给什么资料

已有资料和聊天中已确认内容会优先读取，不要求每次重填。尽量提供：

| 信息 | 用途 |
| --- | --- |
| 产品名、SKU/型号、真实实拍与规格资料 | 保持身份，避免参数/配件串款 |
| 平台；跨境时再给市场、类目和目标语言 | 选择正文、主图、A+及规则模块 |
| 本次范围与用途 | 区分仅策划、文案、概念探索或正式制作 |
| 已有品牌档案、采用稿和素材 | 保留系列风格及已认可取舍 |
| 已知画幅、模块/槽位或后台规则 | 匹配真实容器，不套固定尺寸 |
| 希望保留/改变的内容 | 限定创意、修改范围与预算 |

缺少实物参照时可先做策略、背景或明确标注的概念探索，不能编出真实商品外观和检测结果。没有当前平台规则时可以交草案，明确待核验项。

## 常用任务怎么说

### 国内电商完整制作

> 使用 $ecommerce-visual-strategy，为这款产品做天猫主图与详情页。读取产品资料和现有品牌规范，先安排各图职责，再按布局制作素材和可编辑SVG。交同版本预览及原始素材，做到待我审稿。没有依据的参数不放进画面。

模型读取通用布局、制作和交付参考；不会为了这项任务强制加载Amazon的标题/A+规则。

### Amazon全案

> 使用 $ecommerce-visual-strategy，为Amazon US的【SKU】准备英文标题、五点、商品信息及Listing套图和A+。使用已核实的产品资料，平台规格缺失时列待核验。按规划制作需要的素材，文案和标注独立排入SVG，交我审稿。

只读本次需要的Amazon模块；不默认固定标题上限、图片数量、A+尺寸或移动端比例。A+资格和后台实际模块未提供时交策划/试排草案，不能声称可上架。

### 只做策划或只改文案

> 使用 $ecommerce-visual-strategy，这次只做策划，不生图。给每张图的任务、推荐布局、线框、文案和素材缺口。

> 只修改这张图的标题，保留主体、配色和其他内容，不重生整图。

范围明确时直接完成，不强制走整套制作流程。

### 跨平台或多SKU

> 使用 $ecommerce-visual-strategy，为这些SKU分别做天猫和Amazon US版本，共用有依据的产品事实与品牌风格，平台规则和成稿分别保存。建立任务清单，已有采用稿保留，缺资料的项目单列说明，继续完成其余项目。

品牌解析、受众方法和布局可共享；商品认证、配件、参数不随品牌继承。国内批量按任务清单逐项组织；现有批量脚本只支持Amazon交付v1，不适配所有国内字段。

### 品牌与本地化

> 使用现有品牌档案，只为这个系列调整强调色，说明本次覆盖项，不改品牌默认。

> 将这个SKU的美国站方案改为德国站，保持原始事实和证据，给术语、单位转换、受众依据及版式调整；没有研究的数据标记为假设。

目标语言流畅不等于本地市场研究；重要商用译稿需结合真实材料审阅。机械工具不能验证完整译文语义。

### 实验

> 为这两种附图方案设计A/B实验，明确差异、主要指标、所需数据和停止条件；目前没有实验数据，不判断转化赢家。

> 按提供的真实实验计划和导出数据分析结果，先判断分流和数据是否满足脚本条件，不满足时只做描述性比较。

分析器只支持窄范围的独立用户二项指标与固定样本设计，不能直接解释所有平台统计或证明某种布局普遍更好。

## 制作后会拿到什么

完整视觉制作按实际范围交：

- `design-v01.svg`：独立文字、形状、标注和版式对象；需要保持独立的商品图/背景也分组。
- `preview-v01.png`：与SVG同一版本的渲染预览；最终平台导出按其接受格式另存。
- `assets/`：实际使用的原始位图与素材；不只依赖临时文件。
- `production-notes.md`：素材和生成记录、字体与替代、可编辑范围、阶段/版本、核验缺口与未查项。
- 有正文任务时另交消费者可见文案与稿外依据/缺口；只有Prompt不称成图完成。

文件名可按项目调整，局部改字不强制造一整套空文件。批量时每项保留自己的目录与状态。

位图照片不会因嵌入SVG变成矢量；整张生成场景中已烘焙的商品/阴影也不自动可分离。SVG逐对象调整更适合Illustrator、Inkscape等，PS导入可能栅格化或作为智能对象，不能保证保留文字和分层。字体缺失会影响断行，编辑器兼容需实测。

## 你审稿、改稿与定稿

1. 收到审阅包后，你决定采用或提出反馈；AI交付前会先制作自检，但不能代替你批准。
2. 你可自行编辑，或说“按反馈修改这些对象”。AI以你返回的当前源文件/版本为准，修改另存新版本，保留采用稿。
3. 你完成调整后明确说：

> `design-v03.svg`和`preview-v03.png`是我的正式定稿。请检查这两个文件及关联资料，只报告问题，先不要修改。

4. AI核对指定版本的商品事实、文案、可读性、遮挡、SVG资源/字体/尺寸、源与导出一致性及已知平台规则，列问题、影响、建议和未查项。
5. 需要修复时再说“按问题清单另存修订版”。修订稿需你重新确认；AI不会静默覆盖定稿，也不会自动上架。

只返回PNG时只能查可见画面，无法证明SVG对象仍可编辑。看不到最终文件或规则材料就不能声称完整检查。“已检查范围未发现问题”不保证绝对无误。
