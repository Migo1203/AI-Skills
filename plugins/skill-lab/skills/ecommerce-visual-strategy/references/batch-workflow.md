# 通用多SKU与多平台组织

用于多商品、市场、语言或多平台交付。任务多不意味着默认调用付费批量API。一次任务中逐项完成用户要求的范围，单项缺资料时记录缺口并继续可处理项，不把目录已建当作制作完成。

## 每项保留什么

为每个SKU＋平台＋站点/语言＋交付版本确定唯一任务名，分目录保存真实产品资料、品牌版本、实际素材、平台规则、文案、SVG、同版预览、制作记录、用户反馈与定稿对象。目录名不代替商品身份；正文、素材和事实引用仍要核对。

品牌样式与事实可在确有相同对象时共用，不能复制一份数据只换SKU；同产品不同市场需核对适用性。记录当前阶段：资料待补、策划完成、素材完成、待用户审稿、用户调整中、用户定稿、AI最终检查。成稿保留并读取，续做先检查已有文件，不无故覆盖或重生整套。

清单可用Markdown表：任务名｜SKU｜平台/站点｜语言｜交付范围｜输入位置｜品牌版本｜当前阶段｜交付位置｜缺口。不强制普通对话输出机器JSON。

## 分流

- 国内/其他平台：使用上面的清单逐项制作，按[通用交付](deliverables.md)与[可编辑制作流程](editable-production.md)审阅；当前没有相应平台字段校验器。
- Amazon交付v1：需要机械队列工具时，再读[Amazon批量](amazon/batch-workflow.md)。其manifest只表示Amazon任务，不混装天猫、京东或Shopee交付。不同平台分别建批次；混合任务的总清单由模型汇总。

每项交付报告其实际完成阶段、文件、未检查项。Amazon工具的checked只是JSON机械通过，不是SVG/图片通过，不是用户定稿。纯文案任务不用制造图片目录或等用户定稿整个设计；完整制作到用户审稿停止，用户之后的反馈决定后续动作。

会话中断可读任务清单及文件续做，不声称存在后台持续执行服务。保持版本隔离，不对另一项的假设作全局替换。任务规模扩大时，人工作品审阅、素材整理和生成费用也随之增加。
