# 本地化与受众

适用：跨站点/语言、评价分析、受众简报、当地表达与版式适配。仅改一句且无需这些判断时直接改句。语言流畅不等于市场研究；能翻译不代表已验证当地关键词、受众或广告资格。

## 先建立本次目标

沿用已有SKU和资料，明确站点、语言区域（如en-US、de-DE）、用途、交付字段与当前稿。站点不是语言：Amazon US也可能有其他语言任务。用户没有确定语言时，可按站点提出工作假设，写在稿外。

将资料分开：

- 商品事实：SKU文档、真实规格与适用条件；遵守[事实与规则](evidence-and-policy.md)。
- 受众证据：用户访谈、售后、评价或搜索报告，记录来源、日期、站点、样本范围和筛选方法。
- 设计假设：尚未验证的购买动机、场景或文字偏好，明确标为假设。不能按国籍推断审美和行为。

读取已有资料后再研究真正缺失的信息。具备联网工具且任务需要研究时，查目标站点/类目官方说明及有来源的受众材料，保留实际读过的链接和摘录；无访问能力时列缺口，继续可做部分，不声称做过调研。竞品评价只能形成线索，不能证明本品性能；品牌、价格带、评价激励、时间和差评选择偏差都可能影响结论。少数评论不能推算人群比例。

## 从资料到交付

1. 形成简短的“场景→购买问题→证据/假设→信息优先级→视觉任务”表。受众研究到此必须能改变文案或布局选择，否则不增加空泛画像。
2. 保留原始事实、单位、宣称ID和证据ID。翻译可以改变表达，不能改变力度、适用范围、配件数量、比较对象或认证。遇到当地不适用的事实先核实或移除，不凭经验替换。移除的宣称记录原因。
3. 建术语表：源词、目标词、语言、approved/proposed、使用说明。优先沿用已确认品牌术语；没有数据的关键词称候选词，不称高搜索量。
4. 根据目标语言重写标题、要点和图内短文案。正文与图内文字分别写，后者先保留核心意义，再调整分区、断行或模块，不能为了塞进固定格子删掉必要条件。回译用于发现偏差，不能代替目标语言审阅。
5. 单位换算保留原值、转换值、精度和对应claim_id；重量、容量、包装/产品尺寸分别处理。兼容标准、电压、插头和认证不能靠单位换算完成。
6. 交源/目标对照、受众依据、术语表、转换记录、布局变更和未审事项。有实际图片再看移动端缩放、特殊字符、字体字形与溢出；未看图不得标记视觉审阅完成。

## 可保存表单与检查

复制[本地化表单](../assets/localization.template.json)到本次工作目录。字段包括`sku`、`source_context/target_context`（market、language）、`audience[]`（finding、basis=evidence/hypothesis、source）、`terminology[]`（source、target、status）、`unit_conversions[]`、`omitted_claim_ids[]`和`review`。另在可读交付记录受众样本范围和删改原因，不让研究表单进入消费者正文。

机械检查用同一交付v1格式的源稿、目标稿和本地化表单：

此方法与记录表可用于各平台；下面脚本仍调用Amazon交付v1检查器，含Amazon主图/A+约定，只用于该格式的Amazon稿。国内任务使用源/目标对照、事实核验和人工/模型审阅，不把脚本结果当作国内平台合规结论。

```text
python scripts/audit_localization.py source.json target.json localization.json
```

两稿的`context.language`必须存在。目标稿保留源claim_id和evidence_id；新增事实先修改源资料并重审，不能在翻译环节偷偷添加。工具检查SKU、目标站点/语言对应、遗漏清单、证据记录一致性和已记录的单位换算。

转换值以十进制字符串输入，精度0–6位，按四舍五入ROUND_HALF_UP检查。支持mm/cm/m/in/ft、g/kg/oz/lb、ml/L/fl_oz_us；oz是质量，fl_oz_us是美制液量。其他单位需人工核实。工具不从句子自动提取数值，未记录的错误、条件丢失、同义词误译仍可能漏检。

`review.language/visual`默认`not_reviewed`；填写`reviewed`必须同时记录相应`*_by`与`*_artifact`。这只是审阅记录，不会自动认证其真实性。机械通过只说明已实现检查通过；重要商用稿需要具备目标语言能力的审阅者核对真实资料与最终版式。
