# 多SKU与多站点批量交付

本参考只用于Amazon交付v1的结构化队列，其他平台及混合批次的总清单见[通用批量组织](../batch-workflow.md)。统一入口为`$ecommerce-visual-strategy`。

适用：用户要求多个SKU、市场/语言的成套稿、续做或汇总检查。本模块使用本地队列，不连接付费模型API。模型在当前任务里逐项完成实际草案；脚本负责目录、输入快照和机械检查，不会自动写出文案或图片。

## 清单

清单JSON为`schema_version: 1`和非空`tasks[]`。每项：

- `id`：安全、唯一的任务目录名，只含英文字母、数字、下划线、短横线；不使用Windows保留名。
- `context`：sku、market、language、category；可另记brand_id。
- `input`：已有交付v1草案/证据索引JSON路径。当前批量工具要求该输入可通过单SKU机械检查；原始散乱简报先由模型整理，资料不足的任务单列缺口，不编出可通过的假事实。
- 可选`brand`：品牌档案路径；`series`：系列名；`brand_overrides`：本次样式对象。

文件路径相对于清单目录，也可使用绝对路径。每个SKU/market/language组合唯一；新版本比较使用另一个批次目录，避免覆盖旧版。不同SKU需要各自资料，不能复制一份事实后只改SKU字符串。相同SKU的不同市场也要提供各市场输入，工具不会自动翻译。

可运行例子在项目`examples/demo-batch.json`，使用两个市场的同一合成SKU，仅验证队列；真实多SKU必须换成真实独立资料。

本参考的机器文件属于过程记录；可将整套队列工作目录放在`04_过程记录/批量队列/`，清单引用随位置核对。已经准备好的队列保持内部结构，使用说明链接到各项成稿；不把`prepared.json`等元数据搬进面向用户的成品目录，也不为普通单图交付启动队列。

## 执行

从技能目录调用（路径按实际位置填写）：

```text
python scripts/batch_workflow.py prepare manifest.json --output batch-run
python scripts/batch_workflow.py audit manifest.json --output batch-run
```

1. 沿用已有资料建立清单，检查每项的商品身份与缺口。
2. `prepare`为可处理任务建立独立文件夹，保存`input-delivery.json`、`task.md`、可选`brand-resolved.json`和最后写入的`prepared.json`。原始资料文档不会自动下载/打包；按task.md中的原始输入位置继续读取真实来源。
3. 逐项读取任务、输入、所需技能参考与真实证据，完成用户要求范围的`delivery.json`。实际制作时按[可编辑制作流程](../editable-production.md)在各任务目录保留SVG、预览、素材与制作记录；只要文案/策划不触发生图。本地化任务另存对应记录。已有成稿先读取；未要求改动的采用稿保留，续做只补缺失或明确失败的项目。
4. `audit`汇总`checked`、`failed`、`needs_draft`。错误项不阻止其他项检查。模型应修复有依据可修的失败并复查，不能把准备目录或部分通过报成整批完成。

`prepare`遇到相同输入和完整快照时返回`preserved`，绝不覆盖已存在文件。输入、品牌、任务说明或已准备快照变化会要求换批次目录；中断产生的不完整目录也报错，保留现场，不自动删除。重复/不安全任务标识在任何写入前拒绝。

检查最终context包含目标language，原证据记录不能悄悄改变。增加真实新证据应先更新源输入，改用新批次目录重建快照。检查器不能证明文字和证据语义完全一致，也不能判断图片是否混用了另一款产品；仍需逐项审阅。

## 结果与边界

批次汇总应链接到每项实际交付，并分开列出：文案完成、Prompt完成、成图待验、规则待核验、资料不足。`checked`仅表示机械检查通过。报告默认只输出到终端，需要保存时写到新的报告文件，保留旧结果。

脚本没有后台守护进程、无人值守生成、API重试、生图或上传；模型可在实际制作任务中调用可用生图能力，并按用户审稿阶段停止。会话中断后可重新读取清单和任务文件续做，不声称脚本会持续工作。任务量大时按资料/市场拆批，避免上下文混淆与人工审阅成本被隐藏。`checked`只查JSON，不证明SVG和成图已通过最终检查。
