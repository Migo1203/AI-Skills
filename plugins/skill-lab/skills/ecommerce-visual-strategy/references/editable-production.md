# 可编辑制作、用户审稿与定稿检查

## 默认阶段与交付边界

完整制作任务按以下流程；只要策划、提示词、局部修改或检查时直接完成对应范围，不强制补齐所有阶段。沿用用户已确认的方向和素材。维护技能本身不触发商品生图。

| 阶段 | 执行者与实际产出 |
| --- | --- |
| AI策划 | 事实/用途、图组职责、消费者文字、布局及理由、品牌与产品身份约束、所需素材、目标尺寸与核验缺口 |
| AI按规划制作素材 | 复用合格实拍；需要背景/概念图时调用可用生图能力，保存实际结果与实际生成输入；检查结构和保真问题 |
| AI组装可编辑SVG | 按选定布局分组位图和矢量对象，交SVG、对应预览与原始素材；先做制作自检，标记“待用户审稿” |
| 用户审稿 | 用户给出真实选择或反馈；AI不能替用户批准。收到修改请求后按范围协助，保留采用版 |
| 用户改编或调整 | 用户可自行编辑，AI读取用户返回的当前文件；只改所指对象时不整图重生成，另存修订版 |
| 用户正式定稿 | 用户明确指定文件/版本，记录为用户定稿；不以文件名含final自行推定，也不代替发布授权 |
| AI检查问题 | 检查指定最终源文件及对应导出图，报告发现、依据、建议与未查项；默认只检查，不静默更改定稿 |

完整制作请求已包含所需的本地制作步骤，资料足够就做到审阅包，不逐步反复求确认。缺少影响SKU身份或宣称的关键资料时先处理可做部分并集中说明。用户审稿/定稿需要用户实际输入；不能自行模拟通过后继续。工具不可用不阻碍策划和可做的矢量制作，但必须写明未生成、未渲染或未完成的部分。

## 素材生成与矢量制作分开

- 写实照片、材质、场景与光影是位图任务，使用可用`imagegen`技能或用户明确指定工具。按该工具规则执行；未获授权不切换付费API、模型或安装服务。
- 文字、基础图标、参数卡、箭头、边框、色块、线条与版式直接用SVG对象制作，不用生图结果替代可编辑对象。依据资料制作结构图，不能生成内部结构来补证。
- 优先保留真实商品素材的结构、比例、颜色、Logo和附件；生成结果不能保证SKU完全一致，须实际查看。整体场景里已烘焙的产品与阴影不能宣称可单独移动；需要这种编辑性时应从一开始保留独立产品图层和背景。
- 最终标题、参数、条件和品牌标志尽量后排；已有素材里的印字不能因此凭空消除或编辑。明确哪些是位图中的固有内容，哪些是SVG独立对象。
- 逐图按需要生成，不默认探索大量变体；保留实际生成输入与输出。没有结果文件时只能称策划/Prompt完成。

## SVG交付要求

1. 明确`width`、`height`与`viewBox`，设计坐标与目标像素关系可追溯；不把生成器原始输出尺寸当作平台规格。未核验尺寸时标记试排，SVG不能消除位图像素不足。
2. 使用清楚的独立组和稳定ID，例如`background`、`product`、`headline`、`body-copy`、`callouts`、`icons`；多对象用唯一ID。尽量保留真实`text/tspan`，不要把全文转轮廓或整页栅格化后称文字可改。可另交转轮廓展示版，明确其编辑限制。
3. 图片可嵌入为data URI以方便搬运，同时保存独立原始素材；大图过多时可用包内相对路径，附齐目录。不得依赖临时文件、远程URL或本机绝对路径才能显示。嵌入位图仍是位图。
4. 保持可移动对象独立，谨慎使用复杂滤镜、混合模式、蒙版和`foreignObject`；优先通用SVG结构。不得用脚本或外部网页完成显示。图层是否能原样导入，需在目标编辑器实际打开验证。
5. 记录字体名称、替代字体和许可已知状态，不未经授权打包字体。字体缺失/替换会改变断行与对齐；预览正常不能保证用户电脑字体一致。
6. 用可用渲染器导出与SVG同版本的PNG/JPG预览，实际查看并检查文字、裁切、遮挡与图像清晰度；有移动端用途时再按实际展示尺寸查看。没有渲染能力就标记“源文件已写、视觉未验”，不能标记完整制作自检通过。

## 审阅包组织

默认交付目录（按本次范围，不给局部改字制造空文件；已有明确目录约定时沿用）：

```text
交付/
├─ 01_成品与预览/         同版PNG/JPG、整页与逐图预览；可按需分子目录
├─ 02_可编辑SVG/          SVG母版；可合法附带的字体及许可随源稿保存
├─ 03_原始素材/           实际采用的独立原图、产品照及必要派生素材
├─ 04_过程记录/           实际生成输入、必要依据与机器文件；仅按需保存
└─ 使用说明.md            看图/改图入口、当前阶段、可编辑范围和待办
```

“成品”目录名不代表用户已定稿；说明写清“待用户审稿／用户指定定稿／已检查范围”等实际状态。平台上传素材与带字预览分子目录并说明用途，不把概念预览标成可直接上架。

使用说明作为唯一阅读入口，集中写素材/字体与许可、版本、可编辑范围、实际检查结果和未查项；记录长时链接到过程目录中的一份制作记录。消费者可见正文按任务另交可读文件。保留实际生成输入与采用图的对应关系，可以集中记录，不要求一张图一个JSON。普通制作自检、改稿和审稿不默认额外生成JSON、HTML、检查截图或多份重复报告；只有用户要求交互展示、机器检查/批量队列确需结构化输入，或复现问题需要时才新增相应文件，放到过程目录，用户需要直接打开的交互预览也可放成品目录。

整理已有包时保留原始素材和历史检查记录，修复HTML、SVG、说明和其他运行文件的相对引用；历史记录中保留的旧路径须附迁移说明，不能改写旧检查结论冒充新检查。移动前留可恢复备份，核对资源完整性；不要为目录整洁打散脚本依赖的队列文件。只把文件归类不能证明图像、平台或编辑器兼容已重新检查。

SVG与PS不是等价源格式。逐对象编辑建议用Illustrator、Inkscape或经验证能保留对象的编辑器；Photoshop通常会栅格化导入或作为智能对象使用，不能保证保留文字和矢量分层。用户选择PS时可继续处理位图、另存PNG/PSD并保留SVG母版；没有实际PSD不能称已交付分层PSD。无需强制用户指定编辑器才能先制作通用SVG，未经实测的兼容性标明待验。

## 改稿、定稿与最终检查

用户回传后先确认当前源文件及关联导出图。保留上一采用版，修改另存新版本；用户明确要求覆盖才覆盖指定文件。只给一张PNG时可检查可见画面，不能证明文字/对象仍可编辑。最终检查可用源文件哈希或明确版本+修改时间绑定检查对象，报告列出实际文件和检查时间。

最终检查按风险排序：

- **商品与事实**：SKU、外观、配件、数量、单位、参数、认证、文案力度、条件与资料对应；生成结构、文字/Logo失真不能忽略。
- **文案与视觉**：错别字/翻译、断行、字形、可读性、信息层级、遮挡、对齐、系列一致性和移动端显示。
- **源文件与导出**：SVG能解析/渲染、尺寸与viewBox、重名ID、图片可用、字体记录、对象编辑性；源/预览/最终导出同版，实际位图分辨率满足用途。仅写SVG未打开不能称兼容已验证。
- **平台**：按当前站点、类目与槽位的已核验规则检查尺寸/主图/A+；SVG是编辑母版，最终上架需另导出平台接受的格式。未连接后台不承诺过审。

输出“位置/对象→问题与依据→影响→建议”，分清需修复、建议优化和未验证。没有发现问题写“在已检查范围内未发现问题”，不承诺无误。发现定稿问题先交清单，用户要求修复后改成新候选版，再由用户确认；纯建议不会自动撤销用户的定稿决定。没有SVG、最终图、资料或平台规则时如实列未查项。现有草案JSON脚本不检查SVG/图像，也不负责确认定稿。
