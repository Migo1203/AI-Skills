# Skill 入门与官方参考

## 四个动作分别做什么

| 动作 | 实际含义 |
| --- | --- |
| 保存 | 把 SKILL.md 和所需资源放进 GitHub，便于阅读、版本管理和备份 |
| 安装或启用 | 让目标 Codex 环境发现并加载技能，需要符合该环境支持的安装方式 |
| 使用 | 在已加载该技能的会话中明确调用，或让匹配的任务触发它 |
| 创建 | 把一个具体、可复用的工作方法写成 SKILL.md，验证后继续改进 |

一个 Skill 至少有一个 `SKILL.md`，开头包含 YAML 的 `name` 和 `description`。正文写执行步骤。只有确实需要时再增加 `references/`、`scripts/` 或 `assets/`。

本仓库同时准备了最小的 skill-only 插件。插件将两个 Skill 打包，供支持该格式的 Codex 发现；它没有接入第三方账号或额外 MCP 工具。

## 第一次使用本仓库

1. 在 Codex 中把 AI-Skills 作为当前仓库或工作区打开。
2. 在支持本地工作区插件的版本中，检查插件入口是否发现 **Migo AI Skills**。本仓库的 marketplace 路径按工作区根目录解析，指向 `./plugins/skill-lab`。
3. 按实际界面安装或启用插件；如果未出现，刷新插件列表或重开该工作区，并对照官方的 Build plugins 文档。不同 Codex 产品、版本或组织设置可能支持不同入口，不能仅凭文件存在就认定已安装。
4. 在技能确实可用后，发送：

```text
使用 $study-skill，帮我读懂本仓库的 plugins/skill-lab/skills/plan-ecommerce-visuals/SKILL.md，
说明它的输入、输出和步骤，并给我一个电商海报审稿的小练习。
```

调用前若列表中没有这个技能，也可以先把源文件作为学习材料，请 Codex 阅读和解释；这属于直接阅读文件，不记录为已验证自动加载。

### 当前云环境的实际验证

2026-10-24已用Codex CLI 0.163.0核对命令入口。插件列表尚未列出本仓库插件；尝试登记本地marketplace时，系统返回插件安装目录 `/run/codex-environment/codex-home/.tmp/marketplaces` 为只读，安装未完成。这里不把该结果写成“插件已启用”。

在支持插件且安装目录可写的Codex CLI环境中，可在本仓库目录执行以下命令；它们是按当前CLI帮助整理的安装方式，未在此只读环境中完成安装验证：

```bash
codex plugin marketplace add . --json
codex plugin list --marketplace migo-local-skills --available --json
codex plugin add migo-ai-skills@migo-local-skills --json
```

当前已完成的[第一次练习](第一次练习.md)直接读取技能文件执行，记录了实际结果，可先用于学习。

## 安装已有技能

先提供目标技能的仓库链接、目录和用途。例如：

```text
把这个链接中的技能收录到 AI-Skills，先读取来源与实际依赖，
记录固定版本，放进本仓库的技能插件，检查能否在当前 Codex 中使用。
这次只为这个项目配置。
```

随后完成：读取该技能与它实际用到的资源，确认来源和许可，保留必须的文件，更新技能清单，验证一次真实任务。安装范围从项目内开始；需要用于其他项目时，再选择目标环境支持的用户级或插件级安装方式。

项目目录里的技能文件与当前云会话的技能提供机制可能不同。`.agents/skills/<skill-name>/SKILL.md` 是部分 Codex 环境支持的项目技能布局；本仓库按当前官方插件示例组织。不要为了“看起来已安装”而在多个目录复制同一份技能。

## 创建自己的第一个技能

复制[模板](../模板/SKILL.md.template)到 `plugins/skill-lab/skills/<英文技能名>/SKILL.md`，名字使用小写字母、数字和连字符，并与文件夹名一致。

先回答四句话：

1. 它解决什么具体任务？
2. 用户什么时候会需要它？
3. 要提供哪些输入，按什么步骤处理？
4. 最后应该交付什么？

可以直接让 Codex 执行：

```text
我要创建一个 summarize-design-feedback 技能。
输入是海报审稿意见，输出是按优先级排列的最多三个修改动作。
请依据本仓库模板创建技能，更新技能清单，并用一条示例反馈验证。
```

先让一件事稳定可用，再增加资料或自动化脚本。记录“是否触发”和“是否给出想要的结果”，不要只检查文件存在。
